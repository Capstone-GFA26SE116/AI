## 0. Mục tiêu

- **Làm gì:** Khi một task Flexible chuyển sang `Done` hoặc `Skipped`, AI service tạo **1 memory** cho task đó.
  Memory gồm một đoạn text ngắn mô tả task (để embed) và các con số (lưu ở cột thường).
  Việc embed bằng `gemini-embedding-2` (1536 chiều) chạy nền, user không phải chờ.
  Đây là dữ liệu đầu vào cho FR-09 (tìm việc tương tự) và FR-08 (AI chat).
- **Ai gọi, khi nào:** Backend gọi `POST /learning/task-completed` (endpoint của FR-17, mở rộng thêm),
  sau khi lưu task là `Done` **hoặc `Skipped`**. ⚠️ Backend cần gọi thêm khi task chuyển sang `Skipped`.
- **Tiêu chí xong:**
  - [ ] AC1 — Tạo memory: task Flexible `Done`/`Skipped` → đúng 1 dòng memory (theo `TaskId`). Task `Fixed` hoặc task chưa xong → không tạo.
  - [ ] AC2 — Không chặn user: endpoint trả kết quả mà **không chờ** Gemini. Gemini lỗi hoặc chậm → K_bias (FR-17) vẫn được học và lưu bình thường.
  - [ ] AC3 — Text: gồm title, domain, tóm tắt lý do dừng, ghi chú. **Không có** `Description`, email, số điện thoại, tên client. Ghép bằng code, không dùng LLM.
  - [ ] AC4 — Embedding: model + số chiều lấy từ config. Vector đúng 1536 chiều, lưu được vào pgvector. Mỗi dòng ghi tên model đã dùng (cột `EmbeddingModel`, #21 — đã thêm 2026-10-15).
  - [ ] AC5 — Thử lại: tối đa 3 lần. Vẫn lỗi → `Failed`. Lúc service khởi động, quét và embed lại các dòng `Pending`/`Failed`.
  - [ ] AC6 — Gọi lại: task đã có memory → cập nhật dòng cũ (text mới, embed lại), không tạo dòng thứ 2 (UNIQUE `TaskId`, #22 — đã thêm 2026-10-15).
  - [ ] AC7 — Chi phí: mỗi lần gọi embedding ghi 1 dòng `AIUsageLog` (`Feature = 'Embedding'`), **không trừ** `AiCallsUsed` (`quota_charged = false`).
- **Ngoài phạm vi:** tìm memory tương tự (FR-09) · memory riêng cho từng subtask (`SubTaskId` để trống) ·
  tóm tắt bằng LLM · xóa memory khi task bị xóa (việc của khóa ngoại trong DB, xem #9) · tạo index HNSW (Backend sở hữu schema).

## 1. Bên ngoài — nói chuyện với ai

### API

| Method | Endpoint | Request | Response | Lỗi |
|---|---|---|---|---|
| POST | `/learning/task-completed` (đã có, FR-17) | Không đổi: `{"task_id": "uuid"}` | Như FR-17 **+ trường mới** `memory` | 401 · 404 · 422 như FR-17 |

Trường mới `memory` ∈ `queued` (đã lưu, đang chờ embed) · `skipped` (task không cần memory: Fixed / chưa xong) · `failed` (lưu memory lỗi; K vẫn học bình thường).

```json
{"learned": false, "reason": "task_not_done", "k_old": null, "k_new": null,
 "sample_index": null, "memory": "queued"}
```
Ví dụ trên là task `Skipped`: không học K (FR-17 trả `task_not_done` như cũ) nhưng vẫn tạo memory.

### Database (chi tiết: `docs/database.md`)

- **Đọc:** `Task` (JOIN `Project` lọc user; `Title`, `TaskType`, `Status`, `DomainId`, `EstimatedMinutes`) · `Domain` (`Name`) ·
  `FocusSession` (`StopReason`, ghi chú nếu có cột — kiểm ở bước 0) · `Project.ClientId` → `Client.Name` (chỉ để che tên) ·
  `UserSubscription` (lấy `UserSubscriptionId` cho `AIUsageLog`).
- **Ghi:** `TaskExecutionMemory` ⚠️ (AI ghi — cần Backend đồng ý) · `AIUsageLog`.

### Dịch vụ khác

- **Gemini Embedding API**, model `gemini-embedding-2`, `output_dimensionality = 1536`.
  Model này **không có** `task_type`, thay bằng tiền tố trong text:
  - Lúc lưu memory (FR-19): `title: {title} | text: {body}`
  - Lúc tìm (FR-09, sau này): `task: search result | query: {nội dung}`
- Dùng lại API key và thư viện `google-genai` của FR-10. Không thêm thư viện mới (xem #8).

## 2. Bên trong — logic

### Code nằm ở đâu

- **domain:** `domain/memory_text.py` — ghép text, che thông tin liên hệ (hàm thuần, không gọi gì bên ngoài).
- **application:** `ports/memory_repository.py`, `ports/embedding_client.py`; `use_cases/save_task_memory.py` (tạo/cập nhật dòng `Pending`); `use_cases/embed_pending_memories.py` (gọi Gemini, lưu vector).
- **infrastructure:** `llm/gemini_embedding_client.py`; `db/memory_repository.py`.
- **api:** sửa `routes/learning.py` (thêm trường `memory`, đẩy việc embed vào `BackgroundTasks`); `main.py` (quét lúc khởi động); `deps.py`.

### Luồng xử lý

1. Backend gọi `/learning/task-completed`.
2. Chạy FR-17 như cũ, trong transaction riêng. Kết quả K không phụ thuộc phần memory.
3. `SaveTaskMemory` (transaction riêng):
   - Đọc task (lọc theo user). Không thấy → 404 (như FR-17).
   - `Fixed` hoặc chưa `Done`/`Skipped` → `memory: "skipped"`.
   - Đọc các `FocusSession` của task (cả phiên subtask), tên domain, tên client.
   - Ghép text (xem luật bên dưới), tính T_est, T_act, tỷ lệ.
   - Upsert `TaskExecutionMemory` theo `TaskId`: text, các con số, `EmbeddingModel`, trạng thái `Pending`, xóa vector cũ.
   - Lỗi ở bước này → bắt lỗi, ghi log, `memory: "failed"`. **Không** làm hỏng kết quả FR-17.
4. Trả response ngay. FastAPI `BackgroundTasks` chạy `EmbedPendingMemories` cho đúng dòng vừa lưu.
5. `EmbedPendingMemories` (session riêng, transaction ngắn — #17): đọc text (transaction ngắn) → gọi Gemini **ngoài** transaction
   (tổng cộng tối đa 3 lần gọi, chờ 1 s rồi 2 s — #16) → lưu kết quả + `AIUsageLog` (transaction ngắn).
   Thành công → lưu vector, trạng thái `Done`. Vẫn lỗi → `Failed`. Mỗi lần gọi ghi 1 dòng `AIUsageLog`.
6. Khi service khởi động: chạy `EmbedPendingMemories` cho tối đa 100 dòng `Pending`/`Failed` (cũ nhất trước), chạy nền, không làm chậm việc khởi động.

### Luật & trường hợp đặc biệt

**Ghép text** (`build_memory_text`):
```
title: {Task.Title} | text: {Domain}. {Kết quả}. {Lý do dừng}. Notes: {ghi chú}
```
Ví dụ: `title: Viết landing page cho [client] | text: Coding. Done. Interrupted 2 times, blocked 1 time. Notes: chờ khách gửi logo; sửa responsive lâu.`
- Phần cố định viết tiếng Anh. Title và ghi chú giữ nguyên ngôn ngữ của user (model đa ngôn ngữ).
- Kết quả: `Done` / `Skipped`.
- Lý do dừng: đếm `Interrupted`, `Blocked`, `Other` trên mọi phiên đã kết thúc. Không đếm `Completed`. Không có lý do nào → bỏ phần này.
- Ghi chú: lấy ghi chú không rỗng của các phiên, theo thứ tự thời gian, nối bằng `; `. Không có → bỏ phần `Notes`.
- Giới hạn cả đoạn text **1.000 ký tự**. Quá dài → cắt bớt ghi chú cũ nhất trước.

**Che thông tin** (`mask_contact`), áp dụng cho title và ghi chú trước khi ghép:
- Email → `[email]`.
- Số điện thoại (≥ 9 chữ số, cho phép dấu cách, `.`, `-`, `+84`) → `[phone]`.
- Tên client của project (không phân biệt hoa thường) → `[client]`. Project "Personal" không có client → bỏ qua bước này.

**Cột** (theo schema thật, bước 0): `Content` (text), `Outcome`, `EstimatedMinutes` (T_est, NOT NULL > 0 — task Flexible luôn có), `ActualMinutes` (tổng phiên đã kết thúc, làm tròn phút; không có phiên → 0), `EmbeddingStatus`, `Embedding`, `EmbeddingModel` (⚠️ #21).
- `Outcome` (#23): `Done` → `Completed`, `Skipped` → `NotDone`. Không dùng `Partial`. Phần "Kết quả" trong text vẫn ghi `Done` / `Skipped`.
- Tỷ lệ T_act/T_est và domain **không lưu** (#24): tính lúc đọc (`ActualMinutes / EstimatedMinutes`; JOIN `Task.DomainId`).

**Phiên đang chạy:** task `Done`/`Skipped` mà vẫn còn phiên chưa có `EndedAt` → vẫn tạo memory, chỉ tính các phiên đã kết thúc.
