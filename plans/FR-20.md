## 0. Mục tiêu

- **Làm gì:** Trả số liệu cho màn Dashboard của user:
  (1) tỷ lệ hoàn thành và tỷ lệ xong đúng hạn,
  (2) độ lệch ước lượng theo từng loại việc, kèm xu hướng theo tuần,
  (3) giờ dự kiến so với thực tế theo dự án / khách hàng / task,
  kèm **câu nhận xét dễ hiểu** (vi/en), ví dụ "Bạn thường cần thêm 30% thời gian cho Writing."
  **Code tính hết, câu ghép từ mẫu (giống FR-12). Không gọi LLM.**
- **Ai gọi, khi nào:** Frontend → Backend → AI, khi user mở Dashboard hoặc đổi khoảng thời gian. ⚠️
- **Không gọi LLM, không embedding** → không kiểm / không trừ lượt, không ghi `AIUsageLog`.
- **Tiêu chí xong:**
  - [ ] AC1 — Tỷ lệ hoàn thành và đúng hạn tính đúng định nghĩa #6, #7 trên dữ liệu test tự tạo.
  - [ ] AC2 — Độ lệch theo loại việc chỉ lấy từ dữ liệu đã học (`UserDomainProfile`, `KBiasUpdateLog`);
    câu nhận xét đúng ngưỡng độ tin #3 và vùng "khá sát" #4.
  - [ ] AC3 — Xu hướng gom theo tuần **theo múi giờ của user** (`User.TimeZone`), tuần bắt đầu thứ Hai.
  - [ ] AC4 — Dự kiến vs thực tế: chỉ task Flexible `Done`; T_act dùng đúng `summarize_actual_time` ♻️
    (bỏ phiên đang chạy / chưa xác nhận); mỗi dòng có `estimate_source`.
  - [ ] AC5 — Không câu nào chứa tên nội bộ (`K_bias`, `KBias`, `T_est`, `T_act`, `T_proposed`, `ratio`…), cả vi và en.
  - [ ] AC6 — Đúng user: mọi truy vấn lọc theo `UserId` từ JWT; không có tham số user_id.
    Test: user A không thấy project / client / task của user B.
  - [ ] AC7 — Tốc độ phía server: p95 < 1 s với user có 500 task và 2.000 phiên (đo bằng script seed).
  - [ ] AC8 — User mới / không có dữ liệu: trả 200 với số 0 / mảng rỗng và câu "chưa đủ dữ liệu", không lỗi.
- **Ngoài phạm vi:** heatmap giờ hiệu quả (FR-18 đã có `GET` riêng; Frontend đọc từ đó) ·
  tỷ lệ nguồn T_act (Timer / SelfReported / AutoTimeout) · câu do LLM viết · cache / lưu kết quả vào DB ·
  khóa theo gói (nếu cần thì Backend chặn) · xuất file.

## 1. Bên ngoài — nói chuyện với ai

### API

| Method | Endpoint | Request | Response | Lỗi |
|---|---|---|---|---|
| GET | `/analytics/overview` | query `range` ∈ {`30d`, `90d`, `all`} (mặc định `30d`), `language` ∈ {`vi`, `en`} (mặc định `vi`) | 200 `AnalyticsOverview` | 401 · 404 (user không còn) · 422 |
| GET | `/analytics/breakdown` | query `by` ∈ {`project`, `client`, `task`} (bắt buộc), `range`, `language`, `project_id` (chỉ dùng với `by=task`, tùy chọn), `limit` (chỉ `by=task`, 1–200, mặc định 50) | 200 `AnalyticsBreakdown` | 401 · 404 (`project_id` không phải của user) · 422 |

```json
// AnalyticsBreakdown (by = project | client | task)
{
  "by": "project", "range": "30d", "from": "…", "to": "…",
  "items": [
    {
      "id": "…",                              // project_id / client_id / task_id; null cho nhóm "Không có khách hàng"
      "name": "Landing page ABC",
      "project_name": null,                   // chỉ có khi by = task
      "domain_name": null,                    // chỉ có khi by = task
      "task_count": 6,                        // task có đủ dữ liệu, được tính
      "missing_actual_count": 1,              // task Done nhưng không dùng được giờ thực tế (#9)
      "estimated_minutes": 600,
      "actual_minutes": 750,
      "difference_percent": 25,               // (actual / estimated − 1) × 100 làm tròn; âm = nhanh hơn
      "estimate_source": null,                // chỉ by = task: "user" | "ai"
      "completed_at": null,                   // chỉ by = task
      "text": "Tốn nhiều hơn dự kiến khoảng 25%."
    }
  ]
}
```
- Frontend chỉ hiện `text`; số để vẽ biểu đồ. `code` để chọn icon / màu.
- `by=project` / `by=client`: sắp theo `|difference_percent|` giảm dần. `by=task`: sắp theo `completed_at` mới nhất trước.
- Nhóm / task không có dòng nào đủ dữ liệu (`task_count = 0`) **không** xuất hiện trong `items`.

### Database (chi tiết: `docs/database.md`) — chỉ đọc

- `User` (`TimeZone`) · `Project` (`UserId`, `Name`, `ClientId`) · `Client` (`Name` — chỉ cột này) ·
  `Task` (JOIN `Project` lọc user; `Title`, `TaskType`, `Status`, `Deadline`, `CompletedAt`, `EstimatedMinutes`,
  `AiEstimatedMinutes`, `DomainId`) · `Domain` (`Name`) ·
  `FocusSession` (`TaskId`, `StartedAt`, `EndedAt`, `CaptureMethod`, `IsConfirmed`) ·
  `UserDomainProfile` (`KBias`, `SampleCount`) · `KBiasUpdateLog` (`NewKBias`, `CreatedAt`, `UserDomainProfileId`).
- **Ghi:** không có.

## 2. Bên trong — logic

### Code nằm ở đâu
- domain: `domain/analytics.py` (khoảng thời gian, tỷ lệ hoàn thành, phân loại độ lệch, gom tuần, cộng dự kiến/thực tế, chọn insights) ·
  `domain/analytics_text.py` (mẫu câu vi/en; dùng lại bộ kiểm tên nội bộ của `briefing_text.py` / `reason_writer.py` ♻️ — nếu đang viết riêng thì tách ra `domain/forbidden_terms.py` dùng chung).
- application: `application/ports/analytics_repository.py` · `application/use_cases/get_analytics_overview.py` ·
  `application/use_cases/get_analytics_breakdown.py`.
- infrastructure: `infrastructure/db/analytics_repository.py` (SQL, chỉ đọc).
- api: `api/routes/analytics.py` (`prefix="/analytics"`); nối trong `api/deps.py`; `include_router` trong `main.py`.
- config: `ANALYTICS_BIAS_MIN_SAMPLES` (5) · `ANALYTICS_BIAS_CONFIDENT_SAMPLES` (10) · `ANALYTICS_BIAS_NEUTRAL_BAND` (0.10) ·
  `ANALYTICS_PROJECT_INSIGHT_MIN_PERCENT` (20) · `ANALYTICS_PROJECT_INSIGHT_MIN_TASKS` (3) · `ANALYTICS_INSIGHT_LIMIT` (3) ·
  `ANALYTICS_TASK_LIMIT_MAX` (200).

### Luồng xử lý — overview
1. Đọc `User.TimeZone` (không có user → 404). Tính `from`, `to = now` theo `range` (`all` → `from = null`).
2. **Completion** (#6, #7): 1 truy vấn đếm theo `Status` + đếm đúng hạn.
3. **Domains:** đọc mọi `UserDomainProfile` của user (JOIN `Domain`) → phân loại độ tin (#3) và hướng lệch (#4).
   Đọc `KBiasUpdateLog` trong range → gom tuần (#8). Domain chưa có `UserDomainProfile` → không xuất hiện.
   Sắp: `confident` → `learning` → `none`; trong nhóm theo `|K − 1|` giảm dần.
4. **Insights** (#10 bên dưới): chọn tối đa 3 câu.
5. Ghép câu, trả `AnalyticsOverview`.

### Luồng xử lý — breakdown
1. Như bước 1 trên. `by=task` có `project_id` → kiểm project thuộc user (không → 404).
2. Đọc task Flexible `Done` trong range (+ tên project, client, domain) và **mọi** `FocusSession` của các task đó trong
   1 truy vấn (không N+1).
3. Mỗi task: `summarize_actual_time` ♻️ → dùng được hoặc `missing_actual`.
4. Gom theo `by` (#11), cộng `estimated_minutes`, `actual_minutes`, tính `difference_percent`, ghép câu.
5. Sắp, cắt `limit` (chỉ `by=task`), trả `AnalyticsBreakdown`.

### Luật & trường hợp đặc biệt
- `difference_percent = round((actual / estimated − 1) × 100)`. Câu: ≥ +10 → "Tốn nhiều hơn dự kiến khoảng X%." ·
  ≤ −10 → "Nhanh hơn dự kiến khoảng X%." · còn lại → "Gần đúng dự kiến." (X làm tròn bội 5, như #5).
- Mọi mốc giờ trả về theo múi giờ user (ISO 8601 có offset); `week_start` là ngày (`YYYY-MM-DD`).
- Task Flexible thiếu `Deadline` / `EstimatedMinutes` (dữ liệu lỗi) → bỏ qua, log warning.
- Project `Archived` vẫn tính (số liệu lịch sử vẫn đúng).
- Tên project / client / task là dữ liệu của user → trả nguyên, **không** đưa vào kiểm tên nội bộ.
