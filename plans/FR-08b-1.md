## 0. Mục tiêu

- **Làm gì:** User dán brief của khách vào chat của một project. AI hỏi lại nếu thiếu thông tin, rồi đưa bản nháp
  **milestone + task Flexible** (domain, deadline, số phút AI đoán) kèm danh sách nhắc việc Fixed. User chat tiếp
  để sửa hoặc sửa tay, rồi bấm **Apply** → AI tạo `Milestone` + `Task`.
- **FR-08b chia:** FR-08b-1 (plan này) = brief dạng chữ. FR-08b-2 = đọc tài liệu (`AllowAiDocumentAccess`, file upload).
  Streaming để cuối hoặc bỏ.
- **Ai gọi, khi nào:** Frontend → Backend → AI, từ màn hình project ("Lên kế hoạch với AI").
- **Tiêu chí xong:**
  - [ ] AC1 — Đúng user: mọi endpoint lọc theo `Project.UserId`; cuộc chat / project của user khác → 404.
  - [ ] AC2 — Nhiều cuộc chat / project; mỗi cuộc Apply **đúng 1 lần**; Apply lần 2 → 409.
  - [ ] AC3 — Bản nháp luôn hợp lệ (#14–#17): domain trong danh sách có sẵn, mọi task có deadline, không deadline quá khứ, không trùng task đang có. Sai → thử lại tối đa 1 lần (#24); hỏng → 502, không lưu, không trừ lượt.
  - [ ] AC4 — Chỉ tạo mới: Apply không sửa / xóa milestone hay task đã có. AI không tạo task `Fixed` (chỉ `reminders`, không ghi DB).
  - [ ] AC5 — Nguồn ước lượng: task từ bản nháp AI ghi `AiEstimatedMinutes` = số AI gợi ý (kể cả khi user sửa); task user tự thêm → `AiEstimatedMinutes` trống. `estimate_source` trả `AI` khi giữ nguyên số AI, `User` khi sửa / tự thêm.
  - [ ] AC6 — Số liệu do code tính: tổng theo domain, × K từng domain, tổng giờ, cảnh báo quá tải (#20).
  - [ ] AC7 — Quota & log như FR-08a: kiểm trước, trừ 1 lượt khi thành công, mỗi lần gọi 1 dòng `AIUsageLog` (`Chat`).
  - [ ] AC8 — Riêng tư: brief, tên / mô tả project, title task cũ đã che bằng `mask_contact`; không gửi tên / liên hệ client.
  - [ ] AC9 — Tốc độ: gửi tin p95 < 20 s (đo lại trên gói Gemini trả phí, như FR-08a AC8).
- **Ngoài phạm vi:** đọc tài liệu / file (FR-08b-2) · streaming · tạo task `Fixed` · sửa / xóa việc đã có ·
  tạo domain mới · tự xếp lịch sau Apply (user bấm FR-10) · đặt tên cuộc chat bằng AI.

## 1. Bên ngoài — nói chuyện với ai

### API

| Method | Endpoint | Request | Response | Lỗi |
|---|---|---|---|---|
| POST | `/chat/projects/{project_id}/conversations` | — | 201 `{"conversation_id", "title", "status": "open", "created_at"}` | 401 · 404 · 409 project đã đóng |
| GET | `/chat/projects/{project_id}/conversations` | — | 200 `[{"conversation_id", "title", "status", "created_at"}]` mới nhất trước | 401 · 404 |
| POST | `/chat/conversations/{id}/messages` | `{"message": "…"}` (1–8.000 ký tự) | 200 `ProjectChatTurn` | 401 · 404 · 409 (đã Apply / project đóng / không có gói `Active`) · 422 · 429 · 502 |
| GET | `/chat/conversations/{id}` | — | 200 `{"conversation_id", "project_id", "status", "messages": [...], "latest_draft": ProjectDraft \| null, "applied": bool}` | 401 · 404 |
| POST | `/chat/conversations/{id}/apply` | `{"message_id": "uuid", "milestones": [...]?}` (sửa tay, không bắt buộc) | 201 `{"milestones": [{"id", "title", "deadline", "tasks": [{"id", "title", "estimated_minutes", "estimate_source"}]}], "skipped": [{"title", "reason"}]}` | 401 · 404 · 409 (`not_latest_draft` / `already_applied` / `project_closed`) · 422 |

- Endpoint `/chat/conversations/{id}/…` phải kiểm `Scope = 'Project'`; cuộc chat `Task` (FR-08a) → 404.
- Mọi 409 có `detail.code` như FR-08a #21. Chỉ `messages` tốn lượt.

```json
// ProjectDraft (trong ai_message.draft)
{
  "milestones": [
    {"key": "m1", "title": "Thiết kế giao diện", "deadline": "2026-10-25",
     "tasks": [{"key": "m1-t1", "title": "…", "domain": {"id": "uuid", "name": "Design"},
                "estimated_minutes": 240, "reason": "…"}]}
  ],
  "reminders": ["Họp chốt giao diện với khách — tạo task cố định khi biết giờ"],
  "numbers": {
    "by_domain": [{"domain": "Design", "estimated_minutes": 600, "adjusted_minutes": 780}],
    "total_estimated_minutes": 1800, "total_adjusted_minutes": 2340,
    "days_left": 9, "adjusted_is_hint": false
  },
  "warnings": ["…"]
}
```
- `deadline` milestone = ngày (theo múi giờ user), đã điền sẵn từ deadline project nếu AI để trống.
- UI hiện `estimated_minutes` là "AI đoán — sửa nếu bạn nghĩ khác". Không hiện tên nội bộ (`K_bias`).

## 2. Bên trong — logic

### Code nằm ở đâu
- **domain:** `domain/project_breakdown.py` — kiểu `ProjectDraft`, `DraftMilestone`, `DraftTask`; `check_project_draft`
  (AI và sửa tay), `drop_duplicates`, `resolve_deadlines`, `project_numbers`, `ai_minutes_of` (số AI của task theo `key`, #21).
- **application:** `ports/project_chat_repository.py`; `project_chat_writer.py`; `use_cases/start_project_chat.py`,
  `send_project_chat_message.py`, `get_project_chat.py`, `apply_project_breakdown.py`. Phần chung với FR-08a → helper (#26).
- **infrastructure:** `db/project_chat_repository.py`.
- **prompts:** `project_breakdown_v1.md` + `project_breakdown_samples.json` (10–20 mẫu: brief web, app, thiết kế, viết; tiếng Việt và tiếng Anh; brief thiếu deadline).
- **api:** `routes/project_chat.py`, gắn vào `main.py`, nối `deps.py`.

### JSON Gemini trả về (schema gửi kèm request)
```json
{
  "kind": "question | draft", "reply": "…", "language": "vi | en",
  "milestones": [{"title": "…", "deadline": "YYYY-MM-DD | null",
    "tasks": [{"title": "…", "domain_id": "<enum>", "estimated_minutes": 240, "reason": "1 dòng"}]}],
  "reminders": ["…"]
}
```
Code gắn `key` (`m1`, `m1-t3`) theo thứ tự, điền deadline, bỏ trùng, tính số liệu rồi mới lưu `ProposalJson` (có `version`).

### Luồng gửi tin
1. Đọc cuộc chat + project (lọc user, `Scope = 'Project'`). Không có → 404. Đã `Applied` / project đóng → 409. Tin rỗng / > 8.000 → 422.
2. Kiểm quota (không trừ).
3. Lấy domain `IsActive`, title việc đang có, K từng domain, lịch sử (#18).
4. Ghép prompt (đã che, #19), gọi Gemini, kiểm (#14–#17), thử lại tối đa 1 lần (#24). Ngoài transaction.
5. **1 transaction:** khóa `ChatConversation` (`FOR UPDATE`) → kiểm lại chưa `Applied` → lưu tin user + tin AI (+ `ProposalJson`)
   → `try_charge` → ghi `AIUsageLog`. Mất lượt cuối → rollback, chỉ ghi log `quota_charged = false`, 429 (như FR-08a).
6. Trả `ProjectChatTurn`.

### Luồng Apply
1. Đọc cuộc chat + project (lọc user) → 404. `message_id` phải là bản nháp mới nhất của cuộc này → không thì 409.
2. Có sửa tay → kiểm theo #21; không → dùng bản nháp.
3. **1 transaction:** khóa `Project` (`FOR UPDATE`) → cuộc chat chưa `Applied`, project chưa đóng → domain còn `IsActive`
   (không → 409) → bỏ task trùng với việc vừa được tạo (ghi `skipped`) → tạo `Milestone` → tạo `Task`
   (`Flexible`, `ToDo`, `DomainId`, `Deadline` #16, `EstimatedMinutes`, `AiEstimatedMinutes` #21) → `IsApplied = true`, `Status = 'Applied'`.
4. Trả 201.
